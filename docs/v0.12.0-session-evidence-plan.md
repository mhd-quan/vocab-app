# v0.12.0 Study Session Evidence Plan

## Product stance

This feature is not a covert surveillance layer. It is a visible, consent-first
session evidence system for a local tutoring app. The app records academic
performance plus narrow integrity signals that help the tutor review a session:
answer timing, focus breaks, visible camera check-ins when the student enables
them, and reportable guardrail events.

The product should never claim that a child is "cheating" from a single signal.
The dashboard language stays at "review flags", "attention score", and
"intervention" so the tutor is prompted to inspect context before acting.

  screen recording is enabled per exam: https://web.respondus.com/screen-recording-for-respondus-monitor/
- Honorlock describes a mix of secure browser, screen/webcam recording, AI
  flags, and live pop-in review: https://honorlock.com/online-proctoring-services/
- Proctorio emphasizes configurable exam settings and end-to-end encryption for
  approved representatives: https://proctorio.com/products
- Electron exposes `BrowserWindow.setContentProtection(true)` for best-effort
  native content protection on macOS and Windows, while documenting platform
  limits on newer macOS capture APIs: https://www.electronjs.org/docs/latest/api/browser-window

The useful pattern for Vocab App is not a full exam-lockdown clone. The app is
for ongoing study sessions, so the right model is lightweight evidence plus
friction at suspicious moments, not OS-level device control.

## v0.12.0 shipped scope

1. Evidence data model
   - New append-only `session_evidence_events` table.
   - Event types cover visible notice, camera consent, camera snapshots,
     focus/visibility changes, guardrail overlays, and submitted answer timing.
   - Evidence stays separate from `learning_events`, so SRS/progress remains
     clean and replayable.

2. Student-session instrumentation
   - `SessionPlayer` and `GrammarSessionPlayer` measure `responseMs` from card
     render to submitted/self-graded answer.
   - `progress.recordAnswer` and `progress.recordContentAnswer` store
     `responseMs` in the existing learning-event payload.
   - A session evidence frame records focus loss/return and document visibility.
   - When the app returns from a focus break, the student sees a guardrail
     overlay and must acknowledge it.

3. Camera check-ins
   - Camera capture is off until explicitly enabled in the visible session
     evidence banner.
   - The app asks the OS for camera permission through `getUserMedia`.
   - Snapshots are taken every 5 minutes while enabled, stored under app
     `userData/session-evidence`, and indexed by hash/metadata in the DB.
   - Camera stream is stopped on session change/unmount.

4. Capture guardrail
   - Main BrowserWindow enables Electron `setContentProtection(true)`.
   - This is best-effort: Windows/macOS native APIs can exclude or obscure the
     app in many capture paths, but newer macOS ScreenCaptureKit paths may still
     capture protected windows. The app treats this as a guardrail, not a
     guarantee.

5. Tutor dashboard
   - Dashboard adds a review-flag metric and per-student attention score column.
   - Student detail adds a session evidence module with attention score, review
     flags, focus breaks, camera check-in counts, and per-session timing rows.

6. Secure report export
   - Student detail exports one report file containing progress summary, weak
     items, recent sessions, evidence overview, event timelines, and optional
     camera snapshots.
   - If a passphrase is provided, the report is encrypted with AES-256-GCM and
     PBKDF2-SHA256. Plain exports include a SHA-256 integrity hash.

## Future hardening backlog

1. Tutor policy presets
   - Low stakes: timing + focus only.
   - Standard: timing + focus + student-enabled 5-minute camera check-ins.
   - Exam: camera required, stricter focus overlay, no dictionary popup.

2. Session start consent ledger
   - Record policy version, tutor id, student acknowledgement, and guardian
     consent reference per session.

3. Report verification tool
   - Add a small verifier that decrypts `.vocab-report.enc.json`, checks GCM
     auth, and validates plaintext SHA-256.

4. Review workflow
   - Add "mark reviewed", "false positive", "follow up" and tutor notes to
     evidence sessions.

5. Platform-specific packaging hardening
   - macOS hardened runtime entitlements for camera.
   - Windows installer smoke test on a clean VM for better-sqlite3 and camera
     permission flows.

6. Optional live proctor channel
   - If needed later, add a tutor-visible live status surface. Avoid uploading
     raw media unless the tutor explicitly chooses cloud storage and a retention
     policy.
